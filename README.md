# AFCEA Rocky Mountain Chapter — website

The chapter website, rebuilt on [Payload CMS](https://payloadcms.com) 3 + Next.js (App Router)
so the board can edit everything from `/admin`. Deploys to Vercel with Neon Postgres and
Vercel Blob storage.

## What editors can manage

| Where in `/admin`      | What it controls                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------- |
| **Pages**              | Home, Events, Leadership, STEM Grant (and any new page). Each page = a Topo hero + ordered blocks. |
| **Events**             | Synced from Luma automatically; editors add blurbs, tags, "featured", and Zeffy ticket forms.     |
| **Board members**      | The leadership roster: name, rank, role, group, portrait, contact links, order.                    |
| **STEM programs**      | The programs grid on the STEM Grant page and the four cards on the home page.                     |
| **Media**              | Uploaded images (portraits, covers, OG image).                                                     |
| **Header / Footer**    | Navigation items, "Join AFCEA" button, footer columns and copy.                                    |
| **Site settings**      | Chapter name, address, contact emails, Luma + Zeffy settings, membership URL, STEM total.          |
| **Redirects / Forms**  | Payload redirects plugin and form builder (available for future contact forms).                   |

All content types support drafts, autosave, scheduled publishing, and **live preview** (click
the eye icon on a page or event to see changes before publishing).

## Luma integration

Events come from the chapter's public Luma calendar (`cal-B3ppeWVbSPa2fCP`, set in Site settings).

- `src/luma/client.ts` — fetches `api.lu.ma/calendar/get-items` (public, no key).
- `src/luma/sync.ts` — upserts into the `events` collection by Luma event id. Sync-owned fields
  (title, dates, location, Luma URL, cover) are overwritten on every run. Editor-owned fields
  (featured, hidden, tag, blurb, highlights, Zeffy settings, description, uploaded cover) are never
  touched. Events that disappear from Luma are unpublished, not deleted.
- Triggers: the **"Sync Luma events now"** dashboard button, the daily Vercel cron
  (`vercel.json` → `GET /next/luma-sync` with the `CRON_SECRET` bearer token), the jobs-queue task
  `syncLumaEvents`, or locally `pnpm luma:sync`.

## Zeffy

Zeffy is the payment platform. Any event can enable **Zeffy payments** (Chapter settings tab):
paste the Zeffy ticketing/donation URL and the event page shows a "Get tickets" button and, if
"embed" is on, the Zeffy form inline. There is also a standalone **Zeffy payment form** block for
pages (sponsorships, donations) and a general donate URL in Site settings.

## Local development

```bash
cp .env.example .env            # set POSTGRES_URL to a local Postgres database
pnpm install
pnpm payload migrate            # apply src/migrations to the database
pnpm dev                        # http://localhost:3000, admin at /admin
```

On first run create an admin user at `/admin`, then press **Seed your database** on the
dashboard (or run `pnpm seed`) to load the original site content, then **Sync Luma events now**.

Useful scripts: `pnpm generate:types` (after changing collections), `pnpm payload migrate:create`
(after schema changes — commit the migration), `pnpm lint`, `pnpm test`.

## Deploying to Vercel

1. Create the Vercel project from this repo; add the Neon (Postgres) and Blob integrations.
2. Set `PAYLOAD_SECRET`, `CRON_SECRET`, `PREVIEW_SECRET` (long random strings) and
   `NEXT_PUBLIC_SERVER_URL` (your production URL, no trailing slash).
3. Build command: `pnpm run ci` (runs migrations, then `next build`).
4. After the first deploy: create the admin user at `/admin`, seed, and sync Luma.

`POSTGRES_URL` and `BLOB_READ_WRITE_TOKEN` are injected by the integrations. When the connection
string points at localhost the Vercel Postgres adapter falls back to plain `pg`, and Blob storage
is only enabled when its token is present, so the same code runs locally and in production.

## Project layout

```
src/collections/   Pages, Events, BoardMembers, StemPrograms, Media, Users
src/blocks/        Page-builder blocks: config.ts (fields) + Component.tsx (render)
src/heros/         Topo hero (config + renderer)
src/Header, src/Footer, src/SiteSettings   Globals
src/luma/          Luma client, sync, jobs task, CLI
src/endpoints/seed Original site content + portraits
src/components/    Shared UI (Button, ChamferedCard, Reveal, Topo canvas, ZeffyFrame…)
src/migrations/    Postgres migrations (generated by Payload)
```
